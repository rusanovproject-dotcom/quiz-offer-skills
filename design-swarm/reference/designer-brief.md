# Бриф дизайна: готовое ядро → N визуальных кругов

Передай этот бриф доступному native subagent с ролью дизайн-инженера либо выполни его
сам после завершения смысловой фазы. Специальный тип агента не требуется. Подставь
реальную папку проекта, стиль и число кругов; по умолчанию N=4.

## Задание и владение

Собери локальный прототип одностраничника по готовому содержанию. Владеешь `site/` и
`DESIGN-REVIEW.md`. В проекте могут работать другие исполнители: не откатывай и не меняй
их файлы. Не переписывай смысловое ядро или условия оффера молча; верни противоречие
координатору. У последовательного исполнителя те же границы этапов.

## Сначала прочитай

- `MEANING-CORE-FULL.md` — источник дословных текстов, экранов, оффера и FAQ.
- `materials/SELECTION.md` — отобранные медиа, назначение и права использования.
- Отобранные файлы в `materials/` — просмотри изображения, а не только имена.
- Утверждённый брендбук/стилевое направление и ограничения, если предоставлены.
- Для квиза — переданную архитектуру с ветками, данными и поведением управления.

Отсутствующий обязательный документ назови и запроси. Не изображай прочтение и не
восстанавливай его по имени. Если отсутствие медиа уже отражено в ядре, используй
типографический вариант и разрешённый декор.

## Что собрать

Базовый результат без сторонних инструментов:

```text
site/
  index.html
  styles.css        # при необходимости
  script.js         # только нужный интерактив
  assets/           # только разрешённые локальные материалы
  _screenshots/     # фактические снимки, если доступны
DESIGN-REVIEW.md
```

Используй обычные HTML, CSS Grid/Flexbox, media queries, локальные файлы и минимальный
JavaScript. Нужные reveal-эффекты можно сделать CSS + IntersectionObserver; содержимое
должно оставаться видимым без JS. Учитывай `prefers-reduced-motion`, клавиатуру, видимый
фокус и подписи полей. Анимация помогает чтению и действию, а не скрывает контент.

У существующего проекта сохрани его стек и способ запуска. Не добавляй React,
библиотеки, CDN, аккаунты или сборщик только ради эффектов. Обычная статика должна
открываться локально без внешних UI-сервисов. Для локального сервера, если есть Python,
подставь реальный путь вместо `<папка-проекта>`:

```bash
python3 -m http.server 8000 --bind 127.0.0.1 --directory "<папка-проекта>/site"
```

Открой `http://127.0.0.1:8000/`. Если Python недоступен, открой `site/index.html` в
браузере либо используй существующую команду проекта; не заявляй успешный запуск без проверки.

Фото скопируй с короткими именами в `site/assets/`, сохрани назначение и атрибуцию.
Для разрешённого hero-видео используй poster, `muted`, `loop`, `playsinline` и запасной
статичный вариант. Не подставляй сток или AI-медиа как работы/результаты продукта.
Неизвестные права и водяные знаки — причина исключить материал.

Формы по умолчанию демонстрационные: подпиши это рядом с формой, предотвращай отправку,
показывай «Это прототип, данные не отправлены». Не показывай ложный успех записи или
оплаты. Реальную интеграцию делай только в явно согласованном объёме.

## Стиль

Выбери направление из смысловой фазы. Реальные материалы и брендбук — камертон палитры,
шрифтов и композиции. Не навязывай случайную тему, запрет цвета или универсальный шаблон.
Сохрани голос и ограничения продукта; не меняй обещания ради эффектного заголовка.
Мобильная адаптивность обязательна.

## Нулевой этап: выбор средств

Запиши, какие средства реально доступны для вёрстки, медиа, анимаций и проверки.
Все дополнительные MCP/skills **OPTIONAL**: например, средства UI-компонентов,
`frontend-design`, `theme-factory`, `image-generation`, инструменты обработки видео,
документации и браузерного тестирования. Используй их только когда они доступны,
разрешены и решают конкретную задачу. Пакет не включает и не устанавливает их.

Если ничего дополнительного нет, явно выбери native HTML/CSS/JS. Для декора достаточно
CSS; для медиа — предоставленных файлов; для шрифтов — локального или системного стека.
Не выдавай недоступный инструмент за применённый. В каждом круге можно пересмотреть
выбор, но добавлять эффекты и зависимости ради отчёта не требуется.

## N кругов

1. **Круг 1:** собери все экраны и доступные ассеты. Проверь запуск и основной сценарий.
   Сделай desktop/mobile скриншоты и открой их для просмотра.
2. **Круги 2…N:** по последним снимкам оцени типографику, ритм, отступы, контраст,
   иерархию, фото, переносы, mobile и уместность анимаций. Исправь замечания, пересними
   и сравни. Не отмечай круг завершённым до просмотра новой версии.
3. **Финал:** сохрани последние снимки в `site/_screenshots/`, например
   `round-4-desktop.png` и `round-4-mobile.png`. Запиши реальные размеры viewport;
   обычно достаточно широкого экрана около 1440 px и узкого около 390 px.

Для каждого круга в `DESIGN-REVIEW.md` укажи: просмотренные файлы/размеры, конкретные
проблемы, изменения и оставшиеся вопросы. Если после просмотра правки не нужны,
зафиксируй это; не вноси изменения ради счётчика кругов.

Открой результат и проверь интерактив отдельно от снимков: CTA, якоря, формы, клавиатуру,
отсутствие горизонтального скролла. У квиза пройди ветки, ранние выходы, назад/изменение
ответа, пересчёт результата и правдивый прогресс. Проверь, что тексты и условия остались
такими, как в утверждённом ядре.

Если инструмент браузера/скриншотов отсутствует, не имитируй цикл: проверь доступное,
оставь статус визуальной проверки незавершённым и точную инструкцию ручного просмотра.
Нельзя назвать собственную самопроверку независимым ревью.

## Верни

- Путь к `site/index.html` и проверенный способ локального открытия.
- Что менялось в каждом фактически выполненном круге; пути финальных снимков.
- Проверенные сценарии и реально применённые инструменты.
- Слабые места, недостающие материалы, непроведённые проверки и ограничения прототипа.

Не публикуй и не подключай сбор данных в рамках одного этого брифа. Эти действия требуют
отдельного явно разрешённого задания.
