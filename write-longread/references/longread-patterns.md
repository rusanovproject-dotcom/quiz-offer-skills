# Паттерны линейного продающего лонгрида

Обобщение архитектурных наблюдений. Здесь нет готовых чужих статей,
отзывов или статистики эффективности. Все короткие примеры условные.
Приём выбирается по задаче и фактам; частота его использования в чужих
текстах не доказывает, что он повысит конверсию у нового продукта.

## Базовая последовательность

| Блок | Работа блока | На чём строить |
|---|---|---|
| Хук | Дать причину читать | Узнаваемая ситуация, факт, полезный вопрос |
| Контракт и квалификация | Объяснить пользу и адресата | Задача аудитории, обещание статьи |
| Проблема | Показать текущее затруднение | Наблюдения и слова аудитории |
| Последствия | Объяснить значимость | Подтверждённые издержки, без запугивания |
| Мостик | Сделать решение мыслимым | Принцип, доступный первый шаг |
| Доверие | Обосновать компетентность | Демо, опыт, данные, разрешённый кейс |
| Обучение | Дать инструмент понимания | Рамка, схема, практический пример |
| Переосмысление | Объяснить прошлые трудности | Причины с оговорками, а не универсальное оправдание |
| Механизм и продукт | Показать работу решения | Процесс, состав, границы |
| Контраст | Сделать изменение наглядным | До/после либо явно условные сценарии |
| Возражения | Убрать неопределённость | Ответы на реальные вопросы, ограничения |
| Следующий шаг | Помочь действовать | Понятный CTA и условия |

Не обязательно использовать все блоки по отдельности. Объединяй соседние,
переставляй доказательство ближе к сильному тезису, убирай повторения.

## Отличия трёх воронок

**Presell.** Продаётся следующий шаг знакомства с предложением. В центре —
разбор задачи и подхода; на следующей странице — подробности продукта.
Цена может отсутствовать, но коммерческое назначение перехода не скрывается.
Интрига допустима вокруг вопроса или демонстрации, а не вокруг сути условий.

**Диагностика.** Читатель должен знать, что будет разобрано, с каким результатом
он уйдёт, кто проводит встречу и возможна ли продажа после разбора.
Бесплатность не доказывает отсутствие коммерческой цели. Если есть отбор,
опиши реальные критерии, а не театральный «фейс-контроль».

**Трипвайр.** Полный цикл решения о покупке находится в статье. Разверни состав
так, чтобы каждая часть была связана с применением. Покажи стоимость, доступ,
необходимые навыки, регулярные платежи и правила возврата, если они существуют.
Если отдельных цен на компоненты нет, перечисли пользу без фиктивной суммы ценности.

## Хуки без обязательного числового обещания

- Ситуация → вопрос: «Заявка пришла, а ответственного снова ищут в чате. Где теряется передача?»
- Наблюдение → механизм: «Список задач есть. Почему команда всё равно забывает следующий шаг?»
- Контраст подходов: «Отдельный бот отвечает на вопрос. Связанный процесс ещё и передаёт задачу».
- Проверенный результат → условия: используй цифры только с источником,
  периодом и границами применимости.

Проверь, отвечает ли статья на обещание заголовка. Не добавляй «исследование»,
«секрет», «утечка» или превосходство над всем рынком без фактической основы.

## Удержание

**Открытая петля:** поставь содержательный вопрос и заранее определи место
ответа. Условный пример: «Покажем, почему часть заявок теряется даже после
назначения ответственного». Закрой этот вопрос объяснением, а не новой загадкой.

**Смена масштаба:** принцип → рамка → пример → действие. После общего
объяснения спустись к одному случаю; после случая покажи, где вывод применим.

**Смена ритма:** после плотного абзаца используй короткий пример, вопрос,
схему или промежуточный вывод. Не вставляй разговорные фразы по таймеру.

**Проблема → возможность:** последствие объясняет важность, полезный шаг
возвращает ощущение действия. Не добавляй страх потери статуса или здоровья
и не требуй от читателя узнавать себя в вымышленной драме.

**Callback:** вернись к вопросу, сцене или метафоре открытия и покажи,
как разбор помог увидеть её иначе. Это даёт ощущение завершённости.

## Приёмы для разнообразия

| Приём | Применение | Граница |
|---|---|---|
| Контрактный ввод | Сразу договориться, что разбирается | Не навязывать убеждение читателю |
| Условный персонаж | Провести один пример через процесс | Пометить вымысел, не выдавать за клиента |
| Метафора | Объяснить сложный процесс через знакомый | Не подменять механизм «нейронаучным» словом |
| Метаконтент | Продемонстрировать приём самой статьёй | Показать связь прямо |
| Формула | Сжать взаимосвязь до схемы | Не приписывать коэффициенты без данных |
| Сопоставление | Объяснить применимость подходов | Не карикатурить реальные альтернативы |
| Прозрачность условий | Объяснить состав, цену и ограничения | Без ложной антипродажи |
| Кодовое слово | Упростить предусмотренную запись | Не обещать работающий бот без проверки |

## Оформление для мобильного чтения

Подзаголовок должен объяснять мысль следующего блока. Жирное выделение
помогает просмотреть аргумент, а не кричит каждым словом. Обычно достаточно
коротких абзацев; списки и таблицы нужны для действительно параллельных элементов.
Эмодзи необязательны и следуют тону бренда.

Демо ставь возле объясняемого действия; кейс — возле тезиса, который он
поддерживает. Для любого скриншота нужны доступный файл, допустимое раскрытие
данных и подпись. Планируемое медиа обозначай в указаниях для вёрстки.

CTA описывает действие и ближайший результат: «Посмотреть состав практикума»
или «Выбрать время разбора». Его текст должен соответствовать месту назначения.
Повторяй CTA там, где читатель получил достаточно информации для решения;
нарастающая эмоциональность не обязательна.
